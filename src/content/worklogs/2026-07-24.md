# 24 Jul 2026

Reworked behavora's scoring rules UX: migrated to a 0–100 scale, introduced a bidirectional Impact Slider, added Shopify ecommerce and device-type signals, and refined the presets.

## Projects

### behavora (journey-predictor-api)

**0–100 scale.** Migrated scoring from the previous scale to 0–100 (`feat(scoring): migrate to 0-100 scale`, +148/−110) and removed a redundant `*100` multiplier in the score display.

**Impact Slider.** Replaced the weight slider with a bidirectional Impact Slider spanning −100% to +100%, so a signal can push the score down as well as up (`refactor: transformed the Weight slider into a bidirectional Impact Slider`). The range input was re-styled to match the rest of the maryUI components, and the weight input in scoring rules was replaced with the slider.

**Signals.** Added a device-type signal and enhanced the scoring presets with relevant Shopify ecommerce signals plus a default preset of comprehensive engagement signals.

**Scoring rules layout.** Reorganized the manual configuration section, updated the weight column header, fixed row-click event detail references, and made the buttons responsive.

### All changes

- Migrated scoring to a 0–100 scale; removed redundant `*100` in display
- Replaced weight slider with bidirectional Impact Slider (−100%..+100%)
- Restyled range input to match maryUI; swapped weight input for slider
- Added device-type signal
- Added default preset + Shopify ecommerce signals to presets
- Reorganized manual config section; fixed row-click details and responsive buttons

## Lessons

Bidirectional impact (negative weights) makes the rule language more expressive — a signal can indicate _low_ intent, not just contribute positive evidence. The UI now models that directly.
