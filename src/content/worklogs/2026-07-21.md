# 21 Jul 2026

Split MyPrivateOrder provider saving into draft vs publish with different validation, added unpublish, and cleaned up behavora scoring-rule and session-duration edge cases.

## Projects

### myprivateorder.com

**Draft/Publish split.** Implemented the Save/Publish validation logic: a draft saves without strict rules, while publishing enforces full validation (+211). Refactored the single "Save and Publish" button into separate Save (draft, no full validation) and Publish actions (+84).

**Unpublish.** Added an unpublish action that hides a provider profile and updates the button behavior accordingly.

### behavora (journey-predictor-api)

**Scoring rules.** Restored the "Add new Rule" button to the header, and made a rule value required when it is available in the scoring-rules form.

**Session duration.** Fixed session duration calculation and adjusted validation rules for `string_value`.

**Housekeeping.** Added Filament CSS/JS directories to `.gitignore` and removed generated Filament assets from git (−507). Updated dependencies.

### All changes

- Split provider save into draft (no strict validation) and publish (full validation)
- Added unpublish to hide provider profiles
- Restored Add Rule button to header; value required when available
- Fixed session duration calculation and `string_value` validation
- Ignored and removed generated Filament assets

## Lessons

Draft-vs-publish is a product decision about validation, not persistence: both paths save the same model, only the validation gates differ — so keep the branching in the controller, not the schema.
