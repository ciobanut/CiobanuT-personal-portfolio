# 29 Jun 2026

Added client-side banner page-interaction controls (click-through and background scroll locking) and simplified behavora's speed settings to predefined radio selectors.

## Projects

### behavora (journey-predictor-api)

**Speed selectors.** Replaced the free-form duration input with predefined radio selectors for speed (+26/−15) — a constrained set of options instead of an unbounded field.

### journey-predictor-client

**Page interaction.** Implemented `prevent_page_interaction` from the WebSocket UX settings — when true, the client stops clicks from reaching the page beneath the banner (+39). Implemented background scroll locking triggered by `lock_background_scroll` (+56).

### All changes

- Replaced speed input with predefined radio selectors
- Implemented `prevent_page_interaction` (click-through blocking)
- Implemented background scroll locking

## Lessons

Interaction controls that live on the server config surface need a matching client contract — the WebSocket UX settings and the widget implementation were shipped as one coherent pair.
