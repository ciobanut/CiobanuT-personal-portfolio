# 14 Jul 2026

Removed behavora's `BannerType` model and made a focused GrapesJS banner-editor UX pass: template-drop confirmation, default position, body selection, icons and card actions.

## Projects

### behavora (journey-predictor-api)

**BannerType removed.** Deleted the `BannerType` model (+104/−410) — one less type that a plain string/enum can cover.

**Banner editor flow.** Redirect to the editor right after a banner is created. Fixed the header title switching on toggle.

**GrapesJS editor pass.** A series of template-application improvements:

- Confirmation modal for replacing existing content on banner template drop (+97), with robust category detection and daisyUI styling
- Ensure the body is selected when no component is selected; hide background edit options for the body
- Default banner position to `end-end` and apply on load when unset
- Prevent mutation issues when removing components during template application
- Remove the video block from basic components; update media SVG icons; set category "Banner templates" for banners and countdown timer
- Drop unused `grapesjs-custom-code` and `@silexlabs/grapesjs-fonts` dependencies; remove the toggle-layers toolbar button

**Banner cards.** Enhanced banner cards with additional action buttons.

### All changes

- Removed `BannerType` model (+104/−410)
- Redirect to editor after banner creation
- Added template-drop confirmation modal with category detection
- Ensured body selection; hid background options for body
- Set default position `end-end`; fixed mutation issues on component removal
- Updated media SVG icons and categories; removed unused GrapesJS deps
- Enhanced banner card action buttons

## Lessons

The GrapesJS template-drop path is a classic destructive-action UX: without an explicit confirmation + robust category detection, dropping a banner template can silently wipe existing content.

Removing the `BannerType` model is a reminder to question ORM classes that carry no behavior — a plain string can do.
