# Weekly Retrospective — 29 Jul – 05 Aug 2026

## Projects Worked On

Three projects were active this week, with behavora dominating the volume.

### behavora (journey-predictor-api)

The heaviest week by far — 92 commits. Shopify became a first-class channel: orders now sync into the system via OAuth and real-time webhooks. The signal system was overhauled (condition type migration, usage tracking, wishlist + cart events), and the scoring rules UI gained a unit-of-measure display. Intent-engine work landed toward the end of the week (intent calculators, top-intent display in session tables).

### CiobanuT-personal-portfolio

The portfolio gained the `worklogs` content collection — the publishing infrastructure this very retrospective runs on. Added the `/works/logs` listing page, per-entry dynamic routes, a homepage section, GitHub repo linking for worklogs and projects, and an Astro v7 upgrade.

### MyPrivateOrder.com

Shipped an event-driven welcome notification system with branded mail templates, covering both standard and socialite registration paths.

## Biggest Accomplishments

1. **Shopify integration on behavora** — URL constants extracted into a `UrlConfig` class, order import via Shopify OAuth, and webhook handling for real-time order sync. This turns Shopify into a data source for the journey predictor, not just a separate store.
2. **Signal system refactor** — the `data_type` → `condition_type` migration plus signal usage tracking gave the scoring engine a dedicated, semantically clean type system. Wishlist and action-based cart tracking made the Shopify extension capture richer journey events.
3. **The worklogs collection itself** — building the collection, list components, layouts, and pipeline updates made the daily journaling workflow repeatable. The GitHub repo linking ties every entry back to the code that produced it.

## Challenges

- **Cart event deduplication** — `VisitorJourneyRecorder` collapsed consecutive identical events by signature, so adding the same product twice produced one journey entry instead of two. The fix (including product identity in the signature, exempting cart mutations) was the trickiest bug of the week.
- **The `data_type` → `condition_type` migration** — repurposed generic columns creep in quietly; untangling the coupling between storage and business logic took deliberate refactoring.
- **Webhook error handling** for Shopify timeouts remains an open item.

## Lessons Learned

1. Encapsulate external API endpoint URLs in a config class from the start — it makes mocking and maintenance dramatically easier than inlining URLs.
2. Prefer domain-specific enums over repurposed generic columns. When evaluation logic branches on type, a dedicated field with clear semantics prevents accidental coupling between storage and business logic.
3. Deduplication-by-signature is a blunt instrument. Idempotent, discrete operations (cart mutations) need explicit opt-out, and entity identity belongs in the signature so distinct products aren't conflated.
4. Building your own journaling infrastructure pays for itself — the retrospective you're reading only exists because the journaling pipeline got committed and wired into the portfolio.
