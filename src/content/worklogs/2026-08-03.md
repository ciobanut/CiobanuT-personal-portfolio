# 3 Aug 2026

Extended behavora scoring rules with time/day and page-type conditions, added timezone tracking to visitor sessions, hardened cart detection, and wired GitHub repo-link validation into the portfolio publishing pipeline.

## Projects

### behavora (journey-predictor-api)

**Time/day conditions in scoring rules.** New `ClockRange` support class backs time and day pickers in the scoring rules UI, letting rules match on hours and days of the week (`specs/2026-08-03-datetime-inputs-for-time-day-scoring-signals.md`).

**Page-type conditions.** Added `PageType` enum (66 lines) with multi-select options rendered as badges in the scoring rules UI, plus unit tests.

**Preset confirmation modal.** Applying a scoring-rules preset now goes through a custom confirmation modal instead of an immediate action, with integration test coverage.

**Feature key immutability.** The Filament `Feature` resource now disables editing the feature key and removes delete actions — the key is a stable contract that other rules reference. `EditFeature`, `FeatureForm`, `FeaturesTable` updated with `FeatureResourceTest` (99 lines).

**Cart detection hardening.** `FeatureCalculator` cart detection extended with additional URL patterns and explicit action checks (97 added lines), covered by unit and API integration tests.

**Timezone tracking.** Visitor sessions now capture the visitor's timezone: `TrackVisitorPayload` DTO, `TrackVisitorRequest` validation, `VisitorSession` and `ApiSessionTracker` updated; the Shopify widget (`banner.js`) and `behavora-web` extension send the timezone, with a Cypress e2e scenario.

**Test config.** Raised PHPUnit memory limit in `phpunit.xml`.

### astro-portfolio-website

**GitHub repo-link validation.** New `scripts/validate-worklog-links.mjs` (111 lines) verifies every `github_repos` entry in worklogs and works resolves to a real project; updated `project-mapping.json`, the `engineering-journal` skill rules, and `WorkPost` linking.

**Build fix.** Pinned the Node version via `.nvmrc` + `package.json` `engines` so the Netlify build uses a deterministic runtime.

### All changes

- Added `ClockRange` support class and time/day pickers to scoring rules
- Added `PageType` enum with multi-select badges in scoring rules
- Added preset-apply confirmation modal with integration test
- Enforced feature key immutability and removed delete actions in Filament resource
- Extended `FeatureCalculator` cart detection with URL patterns and action checks
- Added timezone capture to visitor sessions across API, Shopify widget and `behavora-web`
- Added PHPUnit memory limit config
- Added worklog/project GitHub repo-link validation script
- Pinned Node version for the Netlify build

## Lessons

A stable immutable key (the feature key) protects the contracts other rules depend on — preventing edits and deletes is cheaper than migrating references later.

Timezone belongs in the session payload at capture time, not derived at read time — the visitor's context is a fact about the event.
