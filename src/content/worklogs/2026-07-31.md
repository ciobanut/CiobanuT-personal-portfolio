### behavora (journey-predictor-api)

**Unit of measure in features and scoring rules.** Added a `unit_of_measure` column to the `features` table so numeric signal values (e.g., `cart_value`, `product_views`) display their unit alongside condition values in the scoring rules UI. Numeric conditions now render as `at least 5 USD` with a badge, ranges show units, and categorical values render as comma-separated badges. Updated signal names for clarity.

**Cart event deduplication fix.** `VisitorJourneyRecorder` was collapsing consecutive identical events by signature, which broke `add_to_cart` / `remove_from_cart` — adding the same product twice should produce two journey entries, not one. Fixed by including `external_product_id` and `external_variant_id` in the dedup signature and exempting cart mutations from the dedup guard entirely.

**DNS mocking in registration tests.** Added DNS record mocking to `RegistrationTest` so the domain validation check produces deterministic results regardless of whether the test domain actually exists.

**Cleanup.** Removed 5 implemented spec docs (1052 lines) and cleaned up stale unit-of-measure tests.

## Lessons

The journey dedup bug is a good reminder that deduplication-by-signature is a blunt instrument. Cart operations are inherently idempotent at the line-item level (each call is a discrete action), so they need explicit opt-out from the dedup guard. Including product identity in the signature also helps differentiate view events for distinct products on the same page.
