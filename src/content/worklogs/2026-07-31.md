# 31 Jul 2026

Shipped the new `worklogs` content type — a separate collection for daily engineering logs, decoupled from the blog.

## Projects

### astro-portfolio-website

- Defined `worklogs` Zod schema in `src/content/config.ts` with `title`, `pubDate`, `description`, `stack`, and `project` fields.
- Created `GetWorklogs.astro` — a log-style list component (date faded, title prominent, compact rows, clickable).
- Created `WorklogLayout.astro` — a minimal layout for individual worklog pages.
- Added `/works/logs` listing page (30 entries) and `/works/logs/[...slug]` dynamic routes.
- Added `LatestWorklogs` section to the homepage (last 10 entries).
- Updated `engineering-journal` skill to output to `src/content/worklogs/` with new frontmatter format.
- Updated `CLAUDE.md` pipeline to reflect the new output location.

### All changes

- Defined worklogs collection schema in config.ts
- Created GetWorklogs.astro with compact log-style rendering
- Created WorklogLayout.astro for individual detail pages
- Created /works/logs listing page and dynamic routes
- Added LatestWorklogs homepage section to index.astro
- Updated engineering-journal SKILL.md with new output path and frontmatter
- Updated CLAUDE.md pipeline description

## Lessons

Keeping a separate collection for worklogs vs. blog posts makes it much easier to style each content type appropriately. The blog can be polished (cards, images, prose fonts), while worklogs stay compact and utilitarian.
