# 18 Jul 2026

Configured MinIO object storage on MyPrivateOrder.com — bucket management, health checks, resource limits — and shipped a large avatar test suite.

## Projects

### myprivateorder.com

**MinIO setup.** Added MinIO configuration (`.env.example`, `.gitignore`), a command that ensures the bucket exists and sets the public access policy (+162), and an enhanced MinIO service with health checks and resource limits. Added MinIO configuration and tests for bucket management and filesystem integration (+448).

**Avatar tests.** Added a comprehensive test suite for avatar URL rendering and cleanup functionality (+3,901/−1,721).

**Avatar URL refactor.** Streamlined avatar URL retrieval by removing the `asset()` wrapper so URLs resolve correctly against the object store.

**Cookie banner.** Fixed the cookie banner to display correctly by waiting for the `CookieConsent` module.

### All changes

- Added MinIO config, bucket-ensure command with public access policy
- Added MinIO health checks and resource limits
- Added MinIO bucket/filesystem integration tests
- Added avatar URL rendering and cleanup test suite
- Removed `asset()` wrapper from avatar URLs
- Fixed cookie banner load timing

## Lessons

Object-storage onboarding is mostly deterministic glue: a bucket-ensure command plus a health check turns manual S3/MinIO setup into a repeatable deploy step.

Test-first pays off for file lifecycle — the avatar cleanup suite pins the exact behavior storage now owns.
