# 6 Aug 2026

Turned behavora's Banner into a pure presentation object by moving all decision settings (targeting, trigger, relevance signals, display frequency) onto the Offer model, made the Relevance Signals page derive its keys from the intent calculators instead of a hand-picked map, and polished the portfolio dark mode.

## Projects

### behavora (journey-predictor-api)

**Offer becomes the decision object.** Four settings groups moved from Banner to Offer, each as its own commit:

- **Display frequency** — new `OfferDisplayTimingEvaluator`, an Offer page, and a data migration (`move_display_timing_to_offers`) that carries existing per-banner values onto offers; legacy `DisplayTimingEvaluator`, page and routes deleted.
- **Targeting** — new `OfferTargetingEvaluator` (rule + hours/day/weekday fields), `move_targeting_to_offers` migration; `BannerEligibility` trimmed to banner-only concerns.
- **Relevance signals** — new `offer_feature` pivot, `OfferScorer` and `OfferEligibility`; `BannerResolver` now picks the best offer first, then a design banner inside it. `banner_feature` pivot dropped.
- **Trigger** — new `OfferTriggerEvaluator` (rule, `delay_ms`, `is_exit_intent`, `requires_scoring`); both prediction strategies source the trigger from the offer; the exit-intent path finds an eligible offer first, then its banner. Deliberately no migration — legacy per-banner triggers become inert, offers default to prediction.

**Intent-driven relevance signals.** Replaced the hand-picked `OfferType::relevantSignalKeys()` map with runtime derivation: every intent calculator now exposes `signalKeys()`, `OfferType::intentKeys()` maps offer types to the `VisitorIntent` calculators they serve, and `IntentEngine::signalKeysForIntents()` resolves the deduped union. The Relevance Signals page now always reflects the signals scoring actually reads, and surfaces boost/penalty/eligibility signals like `checkout_started`, `cart_viewed`, `price_sort_used`, `seconds_since_last_event`.

### astro-portfolio-website

**Dark mode polish.** Swapped the palette from slate to stone across 37 components for warmer, more readable dark surfaces; fixed black-text-on-dark issues and duplicate `dark-mode` event listeners in `DarkModeToggler`; accessibility styling pass.

### All changes

- Moved display frequency, targeting, relevance signals and trigger settings from Banner to Offer with migrations and tests
- Introduced `OfferScorer`, `OfferEligibility`, `OfferTargetingEvaluator`, `OfferTriggerEvaluator`, `OfferDisplayTimingEvaluator`
- Reworked `BannerResolver` and prediction strategies to be offer-first
- Dropped legacy banner pages, routes and the `banner_feature` pivot table
- Replaced `relevantSignalKeys()` map with runtime `signalKeys()` derivation from intent calculators
- Added `CalculatorSignalKeysTest`, updated `OfferRelevanceSignalsTest` and `IntentEngineTest`
- Updated dark mode colors from slate to stone, fixed black text on dark surfaces
- Fixed duplicate dark-mode event listeners and improved accessibility styling

## Lessons

Making Offer the primary decision object simplified the whole engine: scoring, eligibility, trigger, targeting and frequency live in one place, and Banner is left to design only. The remove-committed work (dropping pages, routes, pivots, legacy evaluators) keeps the model from rotting.

Deriving UI signal keys from the calculators at runtime beats a hand-maintained map — the page can never drift from the logic it configures.
