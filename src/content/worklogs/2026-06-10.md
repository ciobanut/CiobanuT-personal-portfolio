# 10 Jun 2026

Made shadow-DOM the default widget render mode with a new `ShadowBanner` component, and extracted behavora's manual banner sending logic into a dedicated `sendBanner` method.

## Projects

### behavora (journey-predictor-api)

**sendBanner extraction.** Moved manual banner sending logic out of `BannerPredictionPipeline` into a `sendBanner` method (+107/−251) and refactored the code structure for readability and maintainability (+236/−329).

### journey-predictor-client

**ShadowBanner.** Added a `ShadowBanner` component with shadow-DOM rendering support (+202/−33) and made shadow-DOM the default render mode instead of iframe. Removed the banner iframe display and all `BannerIframe` mentions. Kept a banner display logic path supporting iframe and inline options (+367/−272) for backward compatibility.

### All changes

- Extracted manual banner sending into `sendBanner`
- Refactored behavora code structure
- Added ShadowBanner component with shadow-DOM rendering
- Made shadow-DOM the default render mode
- Removed iframe render path

## Lessons

Shadow DOM gives the widget style isolation without an iframe's layout cost — the client-side default flipped once the component proved itself.

Extracting `sendBanner` made the pipeline a thin orchestrator again; the −251 proves how much had drifted into it.
