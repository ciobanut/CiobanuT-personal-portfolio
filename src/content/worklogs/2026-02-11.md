# 11 Feb 2026

Moved taxi-passenger login and register into an `AuthContext`, split `lib/api` into auth and rides modules, and fixed the role validation.

## Projects

### taxi-passenger

**AuthContext.** Implemented an authentication context and updated auth-related components (+90/−29), moving the login/register flow into the context (+66/−77). Login and register now save state in `localStorage` (+131/−71).

**API split.** Split `lib/api.ts` into `auth` and `rides` modules (+196/−201).

### taxi-api

**Role validation.** Fixed user role validation from `'passenger'` to `'client'` in registration (+1) and enhanced registration validation with a correct user resource instance (+19). Multiple `AuthController` updates for the SPA flow.

### All changes

- Implemented AuthContext (login/register in context)
- Split lib/api into auth + rides
- Persist auth state in localStorage
- Fixed role validation to client

## Lessons

Centralizing auth in a context means every screen reads session state from one place — the split API modules (auth/rides) make the dependency direction obvious.
