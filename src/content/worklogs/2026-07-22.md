# 22 Jul 2026

Built a reusable Alpine Tag Input component for behavora's campaign signal, improved provider ordering and URL handling on MyPrivateOrder.com, and centralized WebSocket config in the client.

## Projects

### behavora (journey-predictor-api)

**Reusable Tag Input.** Extracted a reusable Alpine.js Tag Input component (+161) for the Campaign signal in scoring rules. Four follow-up fixes to land it cleanly: `Alpine Expression Error: tagInput is not defined` (+60/−80 rewrite), saving correct tags before removing others, new tags appearing instantly in the list, and consistent HTML/classes.

**Add Rule modal.** Disabled already-used signals in the "Add Rule" modal and added an `x-choices-offline` multi-select for the Traffic Source signal. Updated the Cart Value label to "Cart Total Value (monetary)" in `SignalKey`.

### myprivateorder.com

**Provider ordering.** `PortController` / `ProviderController` now order providers by claimed status so claimed providers rank first. Draft provider creation now includes port and country associations.

**Website URL normalization.** Added URL normalization for better UX (+103).

**Housekeeping.** MinIO healthcheck tweak, axios bumped to 1.18.1, and a 401-line "rules for tests" doc added.

### journey-predictor-client

**Centralized WS config.** Extracted WebSocket connection settings into a centralized environment config with documentation, instead of scattering them.

### All changes

- Added reusable Alpine Tag Input component for campaign signal
- Fixed tagInput Alpine error, tag persistence and instant display
- Disabled used signals in Add Rule modal; added Traffic Source multi-select
- Ordered providers by claimed status; drafts carry port/country
- Added website URL normalization
- Centralized WebSocket env config in the client

## Lessons

A small component like Tag Input needs its state transitions nailed down (persist → re-render) before it's reusable — four of the day's commits were exactly that.
