# 3 Mar 2026

Introduced `ClientSessionContext` and `DriverSessionContext` to taxi-api, renamed `rides` to `rideRequests` for clarity, and added a role-based home controller.

## Projects

### taxi-api

**Session contexts.** Introduced `ClientSessionContext` and `DriverSessionContext` (+652/−255) so client and driver UIs have typed session state.

**Rename.** Renamed `rides` to `rideRequests` across the codebase (+204/−201) and `MyRides` to `MyRideRequests` (+20/−13); reorganized component folders into `driver` and `client`.

**Routing.** Added a `HomeController` that redirects users by role (+28/−3) and implemented ride request management with new components and API integration (+169/−35).

### All changes

- Introduced Client/Driver session contexts
- Renamed rides → rideRequests
- Added role-based HomeController
- Reorganized components into driver/client folders

## Lessons

Typed session contexts per role remove the "which context am I in" branching that plagues shared UIs — each surface reads from the context it was designed for.
