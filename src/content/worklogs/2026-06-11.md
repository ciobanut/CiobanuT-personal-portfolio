# 11 Jun 2026

Made client-side session tracking more reliable (keepalive `session_end`, heartbeat on tab visibility, missing page fields), added `action_target` to the journey model, and dropped inline banner rendering.

## Projects

### behavora (journey-predictor-api)

**action_target.** Added the `action_target` field to the `VisitorJourney` model and updated related logic (+39/−5). Regenerated Swagger docs.

### journey-predictor-client

**Session tracking reliability.** Made `session_end` tracking reliable using `fetch` keepalive plus a visibility-change hook (+76/−32). The heartbeat now respects tab visibility — stops when the tab is hidden, resumes when visible, and sends `tab_visible` (without `action_target`) on return. Added 4 missing fields (`page_title`, `page_description`, `referrer_url`, `canonical_url`).

**Widget rendering.** Display only the ShadowBanner when a banner should show — removed the Inline (green) render path (+10/−134). Removed country detection from the client.

**API URL.** If the client specifies `data-api-url` it is used; otherwise the default is used.

### All changes

- Added `action_target` to VisitorJourney + logic
- Made session_end tracking reliable with keepalive + visibility hook
- Heartbeat respects tab visibility; sends tab_visible on return
- Added page_title/description, referrer_url, canonical_url fields
- ShadowBanner-only widget rendering (removed inline)
- Removed client country detection

## Lessons

`fetch` keepalive plus a visibility-change handler is the reliable way to flush `session_end` — the old path lost events when the tab closed.

The render surface is an interface decision: committing to ShadowBanner-only removed a whole second render path.
