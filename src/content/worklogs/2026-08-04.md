# 4 Aug 2026

Shipped behavora's intent engine: eight `VisitorIntent` calculators that score a session, persisted intent on predictions, and a top-intent badge surfaced across the session dashboard.

## Projects

### behavora (journey-predictor-api)

**Intent calculators.** Implemented eight calculators under `app/Services/IntentEngine/Calculators/`, each scoring a distinct visitor intent: `CartAbandonmentRisk`, `ComparingProducts`, `HighPurchaseIntent`, `LowEngagement`, `PriceSensitive`, `ProductResearch`, `ShippingSensitive`, `Undecided`. Shared scaffolding via `AbstractIntentCalculator` and `IntentCalculatorInterface`; `IntentEngine` orchestrates them and returns the highest-scoring intent for a session.

**Intent persistence.** Added an `intent` column to the `predictions` table (`2026_08_04_000000_add_intent_to_predictions_table`). Both `AdminWeightsPredictionStrategy` and `MlPredictionStrategy` now persist the resolved intent, with an integration test (`IntentPersistenceTest`) and a shared setup helper for consistent scaffolding.

**Top-intent display.** New `VisitorIntent` enum holds canonical intent keys and labels; `TopIntentResolver` picks the top intent from a session's predictions and `TopIntentResult` carries it into the UI. Session tables now render a top-intent badge, and the sessions show page displays it in the Purchase Intent column with an `intent-label` badge component (score included, with fallback behavior when no intent matches).

**Design doc.** Wrote `specs/2026-08-04-intent-engine-design.md` (437 lines) covering intent detection and display logic; removed the superseded datetime-inputs spec.

### All changes

- Added 8 intent calculators with unit tests each
- Added `IntentCalculatorInterface`, `AbstractIntentCalculator`, and `IntentEngine` orchestrator
- Added `intent` column to predictions with persistence in both prediction strategies
- Added `VisitorIntent` enum, `TopIntentResolver`, `TopIntentResult`
- Added `intent-label` badge component with scores and fallback
- Rendered top-intent badge in session tables and Purchase Intent column
- Wrote the intent-engine design spec

## Lessons

Modeling intents as independent calculators behind one interface makes the engine extensible: adding an intent is a new calculator plus a test, and the orchestrator stays untouched.

Persisting the resolved intent on the prediction (not recomputing at read time) keeps dashboards fast and keeps the display logic (top-intent resolver) separate from the scoring logic.
