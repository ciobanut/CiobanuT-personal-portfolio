# 12 Jun 2026

Enhanced auto_sender's job-detail modal, refactored behavora-demo's environments to read from `.env`, and fixed duplicate WebSocket connections on the client.

## Projects

### auto_sender

**Job detail modal.** Enhanced job detail fetching and parsing and improved the modal display for requirements (+441/−102). Updated the PHP version matrix to 8.4 only and ran a composer update.

### behavora-demo

**Environment refactor.** Renamed env variables to use the `NEXT_PUBLIC_` prefix (without it they never reached the client), and updated config/environments to read from `.env` instead of hardcoded values (+64/−237). Made prod the default environment and removed the `/env` link from the main page. Renamed the Experiments page to Environment (+630/−264), added fake pages (+721), login credentials as a query param, and a local dev script.

### journey-predictor-client

**WS lifecycle fix.** Fixed duplicate WebSocket connections by separating the Pusher lifecycle from channel subscriptions (+17/−3) — one shared connection instead of one per subscription.

### All changes

- Enhanced auto_sender job-detail modal and parsing
- Pinned PHP matrix to 8.4
- Refactored demo envs to .env with NEXT_PUBLIC_ prefix; prod default
- Renamed Experiments → Environment; added fake pages
- Fixed duplicate WebSocket connections (Pusher lifecycle split)

## Lessons

NEXT_PUBLIC_ is a hard contract for Next.js client env vars — without the prefix the value never reaches the browser, which is exactly the class of bug the rename fixed.

One WebSocket per subscription multiplies connections; separating lifecycle from subscription lets one socket serve many channels.
